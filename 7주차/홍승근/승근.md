## 문제

### 1.배경
>당신은 글로벌 서비스용 검색어 자동완성 시스템 설계자입니다.
다양한 언어를 지원하며, 천만 명 이상의 사용자가 동시에 이용하는 대규모 서비스로, 빠르고 정확한 자동완성 기능 제공이 핵심입니다.

### 2. 요구 사항
- 트래픽 규모
  DAU(Daily Active Users)가 천만 명으로 대규모 트래픽을 감당할 수 있어야 합니다.

- 다국어 지원
  한국어, 영어, 일본어 등 여러 언어를 지원해야 합니다.

- 자동완성 검색어 일치 범위
  사용자가 입력하는 단어가 자동완성 될 검색어의 시작 부분이거나 중간 부분에 위치할 수 있습니다.

- 빠른 응답 속도
  사용자 입력에 따라 최대 100ms 이내에 자동완성 결과가 반환되어야 합니다.

- 추천 결과 수
  화면에 5개의 자동완성 검색어가 표시되어야 합니다.

- 인기 변동 반영 (선택 사항)
  특정 검색어의 인기가 갑자기 높아지는 경우, 해당 인기도 변화가 실시간 혹은 근접 실시간으로 자동완성에 반영되어야 합니다. (10분 이내 반영)

위 요구 사항을 기반으로, 효율적이며 확장 가능한 검색어 자동완성 시스템 아키텍처를 설계하십시오.

## 1. 설계 방안
- 사용자가 입력하는 단어가 자동완성 될 검색어의 시작 부분이거나 중간 부분에 위치할 수 있다
  - 트라이 자료구조만으로 중간 부분을 처리하기에 비효율적으로 보임
    - 중간 문자열을 처리하려면 모든 접미사/부분 문자열을 노드로 추가해야함
  - 따라서 이를 해결할 수 있는 엘라스틱 서치를 사용해 검색 부분을 담당
- 다국어 지원
  - 엘라스틱 서치의 인덱스를 언어별로 관리
    - ex) ko, en, mix
  - 만약 사용자가 한국어를 검색하려하면 ko + mix 구조로 조회
- 인기가 높아진 검색어의 경우 실시간으로 자동완성에 반영되어야 한다
  - 엘라스틱 서치의 업데이트는 문서를 재작성하는 것이기 때문에 실시간 반영에 부적합함
  - 따라서 엘라스틱 서치는 검색어와 비슷한 후보를 걸러내는데 사용하고, 레디스로 검색어의 인기량을 관리
  - 엘라스틱 서치에서 후보들을 가져와 레디스에서 해당 인기량들을 조회해 TOP 5를 도출

## 2. 컴포넌트 구조
- ElasticSearch
- Kafka Streams
- Redis (ZSET)

## 3. 동작 흐름

### 3-1. 자동완성 요청
1. 클라이언트가 검색어를 입력하면 비동기로 요청을 진행
   - 무슨 언어인지 확인
2. API Gateway를 거쳐 검색어 자동완성 API로 전달
3. 자동검색완성 API는 해당 언어 + mix 인덱스를 ElasticSearch에서 조회
4. Elasticsearch에서 반환된 후보 검색어 리스트를 Redis의 ZMSCORE를 이용해 인기량들을 가져옴
5. 애플리케이션에서 인기량들을 기준으로 TOP 5개를 추출하여 클라이언트에 반환

### 3-2. 검색 요청
1. 사용자가 검색어를 입력하고 검색 버튼을 누르면,
검색 API가 결과를 반환함과 동시에 검색어 이벤트를 Kafka로 발행
2. Kafka Streams가 이벤트를 소비하여 Redis에 검색어 인기량을 반영하고, 
Elasticsearch 업데이트가 필요한 경우 별도의 토픽으로 전달
3. Scheduler가 일정 주기로 해당 토픽을 읽어 Elasticsearch에 Bulk 업데이트 수행
