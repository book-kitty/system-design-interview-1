

- 이벤트 발생 : 사용자의 요청을 AJAX로 처리하여 페이지 새로고침없이 GET 요청 발생

- 시스템 구조 : 3단계에 걸친 검색 구조를 통해 성능 최적화

### 1. Redis Cache 확인 (사용자 검색어에 해당하는 자동완성 결과를 Redis에서 우선 조회)
   - 요청 키에 해당하는 자동완성 결과를 Redis에서 먼저 조회한다. (저장되는 key에 lang 키워드도 포함)
   - Cache Hit : 그 즉시 결과 반환
   - Cache Miss : 아래의 단계로 진행

### 2. 인메모리 Trie 방식 (검색어 데이터를 메모리에 Tree형 자료구조로 올려두고 DB 조회 없이, prefix 기반 조회)
   - Redis에 캐시되지 않은 검색키워드는 서버 내 메모리에 존재하는 Trie 구조를 탐색 (메모리에 빌드하고 전역 캐시처럼 들고 다니는 구조)
   - Trie는 애플리케이션 초기 구동 시에 DB로부터 미리 로딩되어 있으며, 상위 인기검색어 중심으로 구성
   - Trie Hit : 그 즉시 결과 반환 후에 Redis Cache 저장
   - Trie Miss : 아래의 단계로 진행

### 3. Redis N-gram 방식 (N-gram : 문자열을 N개의 연속 문자로 쪼개는 방식)
   - 중간 포함 검색을 위해 "people" 키워드를 예시로 들어서, 3-gram인 경우 "peo", "eop", "opl"..등의 조각으로 쪼개어 키로 설정하여 "people" value를 반환할 수 있도록 Redis에 Sorted Set
   - ZREVRANGE 키워드를 통해 높은 빈도인 스코어를 갖는 데이터 순으로 우선 반환  



### [데이터 갱신 전략]
1. Redis Cache
   - 저장 시점 : 레디스 캐시, Trie, N-gram에서 Hit 시
   - 저장 주체 : API 서버
   - 저장 방식 : 레디스 내 Set

2. 인메모리 Trie 확인 
   - 저장 시점 : 매일 자정 및 서버 재구동 시
   - 저장 주체 : 스프링 배치잡 
   - 저장 방식 : MySQL 내 상위 N만건 조회 후 메모리에 로드

3. Redis N-gram
   - 저장 시점 : 매일 자정
   - 저장 주체 : 스프링 배치잡
   - 저장 방식 : MySQL 내 상위 N만건 조회 후, 각 검색어를 N-gram으로 분해하여 Redis에 저장
